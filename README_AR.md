# دوجري | DUGHRY
**كل احتياجاتك في مكان واحد**

هذا المستودع يحتوي حالياً على نموذج Flutter أولي لتطبيق دوجري. هذا الملف يوضح ما هو موجود فعلاً وما لم يتم ربطه بعد، حتى لا يتم اعتبار الشاشات التجريبية خدمات تشغيلية مكتملة.

## ما تم تنظيمه في نسخة التطوير
- إضافة المحافظات المصرية الـ27 بالترتيب المعتمد للمشروع.
- جعل القاهرة والجيزة متاحتين، والمنيا متاحة جزئياً في مركز العدوة فقط، وباقي المحافظات قيد الإطلاق.
- فصل اختيار المحافظة/المنطقة عن حالة GPS؛ اختيار العنوان لا يعني أن GPS يعمل.
- عرض المحافظات في شبكة اختيار بدلاً من قائمة منسدلة طويلة.
- تصفية العروض التجريبية بحسب المحافظة المختارة والقسم، وعدم إظهار منتجات محافظة أخرى.
- توحيد الأقسام الرئيسية العشرة وفق نطاق دوجري.
- توضيح أن الطلبات والتسجيلات الحالية تحفظ محلياً كتجربة ولا ترسل إلى خادم.

## الإمكانيات الموجودة في الكود حالياً

| الجزء | الموجود حالياً | الحالة الفعلية |
|---|---|---|
| الواجهة الرئيسية | شاشة بداية، هوية دوجري، اختيار منطقة، إشعارات ثابتة | واجهة تجريبية |
| المحافظات | 27 محافظة، والقاهرة والجيزة متاحتان والمنيا/العدوة جزئياً | بيانات ثابتة داخل التطبيق |
| الأقسام | مطاعم، ملابس، عمال فنيين، أجهزة كهربائية، قطع غيار، حجز دكتور، فنادق، أدوات منزلية، مواصلات، سوق دوجري المفتوح | بطاقات أقسام؛ بعضها بلا عروض بعد |
| المنتجات والخدمات | 4 عناصر تجريبية | ليست بيانات متاجر حقيقية |
| السلة | إضافة/زيادة/تقليل/حذف وحساب الإجمالي | تعمل داخل ذاكرة التطبيق فقط |
| الطلبات | إنشاء سجل طلب من السلة وعرضه | محلي وتجريبي؛ لا يرسل للتاجر |
| الحسابات | نماذج عميل/تاجر/فني/طبيب | تسجيل تجريبي دون OTP أو حسابات خادم |
| موافقة الإدارة | قائمة طلبات وتغيير حالة الطلب | محاكاة محلية فقط |
| الإدارة | شاشة دخول ولوحة مراجعة | غير آمنة للإنتاج؛ رمز الدخول موجود بالكود |
| الإشعارات | نافذة إشعارات وعلامة غير مقروء | محتوى ثابت؛ لا توجد خدمة إشعارات |
| العناوين وGPS | اختيار محافظة ومنطقة | لا يوجد حفظ عناوين متعدد أو خرائط أو GPS فعلي |
| الدفع والتوصيل | لا يوجد تكامل | غير منفذ |
| السوق المفتوح | قسم ظاهر ضمن الأقسام | لا توجد إعلانات أو مراجعة نشر فعلية |
| الفنادق والمواصلات وقطع الغيار والمطاعم والملابس | أقسام ظاهرة | لا توجد بيانات أو عمليات حجز/طلب متصلة |

## ما لا يزال مطلوباً قبل اعتبار التطبيق جاهزاً
1. استكمال هيكل مشروع Flutter وملفات Android/Gradle وملفات التشغيل والاختبارات.
2. فصل الملف الكبير إلى مجلدات واضحة: app, core, features, data, models, services, widgets.
3. إضافة قاعدة بيانات وخادم API وتسجيل دخول آمن وصلاحيات أدوار.
4. تنفيذ OTP والتحقق من رقم الهاتف، وعناوين العميل ونقطة التسليم على الخريطة.
5. ربط التاجر والفني والطبيب بموافقات الإدارة الحقيقية وإخفاء الملفات غير المعتمدة عن العملاء.
6. تنفيذ دورة الطلب: إنشاء، إرسال للتاجر، قبول/رفض، تجهيز، تسليم، إلغاء، وتتبع الحالة.
7. تنفيذ حجز الأطباء والفنادق والمواصلات والسوق المفتوح وإدارة الإعلانات.
8. إضافة صور وأصول الهوية وخط عربي محلي، بدلاً من الاعتماد على عناصر وأيقونات فقط.
9. إزالة كلمات المرور التجريبية والبيانات الثابتة، وتأمين لوحة الإدارة من جهة الخادم.
10. تشغيل `dart format` و`flutter analyze` والاختبارات وبناء APK فعلي على بيئة Flutter.

## تنبيه مهم
وجود شاشة أو زر في النموذج لا يعني أن الخدمة متصلة أو جاهزة للعمل التجاري. لا تستخدم هذه النسخة لاستقبال طلبات أو بيانات عملاء حقيقية قبل تنفيذ الخادم والحماية والاختبارات.
